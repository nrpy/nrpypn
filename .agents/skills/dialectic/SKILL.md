# NRPyPN Dialectic

Read [the required shared protocol](../../review-protocol.md) for modes, independence,
coverage, budgets, validation, and delivery, and the [NRPyPN agent guide](../../README.md)
for source locations and scientific standards. Load only the relevant source and
reference notes in addition to these instructions; distribute these files together.

Use exactly two independent seats. Root owns live writes; seats never delegate
or edit live targets. Default to `review`, including scientific documentation and
instruction changes. Cross-model review requires an explicit user request.
Use `design` or `dual-build` only under the shared criteria and limits.

## Roles

**Post-Newtonian scientific verifier.** Check the cited equations, exact symbolic
coefficients, mass and spin conventions, momentum signs, PN truncation, physical
limits, and executable results. Trace Hamiltonian changes through orbital frequency
and momenta. Distinguish independent derivations from transcription agreement and
stored-result regression; check affected radial-momentum approaches at matching order.
Check general Hamiltonians with independent momenta before imposing centre-of-mass
or circular-orbit substitutions that can hide terms.

**Integration and simplification reviewer.** Check NRPyPN's shared symbols and
vector helpers, SymPy types, public evaluator and CLI, Python compatibility,
`nrpy` dependency use, reference-data ownership, module checks, and equation notes.
Check downstream effects and stale references. Prefer the simplest sufficient
implementation; reject unsupported abstractions and compatibility machinery.

For non-software work, use a first-principles analyst and a domain/implementation expert.
Roles add complementary scrutiny, not duplicate test suites.

## Completion

Follow-ups cover the delta, open findings, and code/docs impacts only. Root must
[deliver and verify](../../review-protocol.md#delivery) the selected result at ALL
intended authorized `/work/` paths; a verdict or `DRAFT COMPLETE` is not delivery.
Preserve blocked drafts separately, never as accepted changes.

If the protocol is missing, do not invent approval. Preserve produced drafts in a
fresh `/work/review-results/<task>/unapproved/` area, verify copies, and report the
missing file. Explicit user write/output restrictions control.
